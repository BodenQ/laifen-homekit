# 自适应照明：原生与亮度解耦

默认 `adaptiveLightingMode: "apple"` 完全使用 Homebridge/HAP 原有行为。`independent` 是本项目的可选偏好：只把计算色温的参考亮度固定为 `adaptiveReferenceBrightness`（默认 70，允许 1–100），不会设置或伪造真实亮度。它保留 Apple 的时间曲线，但有意改变与实际亮度联动的行为；不声称这是 Apple 官方新增模式或认证。

## 计算方式

Apple 曲线的每个点给出色温 T（mired）、亮度系数 F、过渡时间及可选停留时间。原生计算为：`round(插值(T) + 插值(F) × 当前亮度)`。

解耦模式把参考亮度 R 限制在 Apple 本次计划允许的亮度范围内，对临时曲线端点作 `T′ = T + F × R`、`F′ = 0`。由于 R 固定，先投影再线性插值与先插值再代入 R 数学等价。投影阶段不取整，仍由 HAP 在插值后统一取整，并遵守灯具的 mired 上下限。

## 保留什么

使用 HAP 的 AUTOMATIC 调度器，只覆盖公开的 `getCurrentAdaptiveLightingTransitionPoint()` 方法，返回端点副本。原始曲线、序列化内容和 HomeKit 读回内容不变；没有修改 node_modules，也没有复制一套时钟调度算法。

因此停留时长、分段过渡、起始时间、时钟偏差、更新时间、通知节流、每天的新计划、重启恢复、曲线到期及手动色温退出均仍交给原控制器。亮度事件可能触发一次重新计算，但相同时间的色温结果不会随真实亮度变化。关灯期间仍仅缓存目标，不因色温更新开灯。

每段的 T 和 F 都参与投影，不是给最终 K 值加固定偏移，也不是用一条自编的作息曲线替代 Apple 计划。70% 不等于固定色温；早晚仍暖、白天通常更冷。

## 配置和回退

在 Homebridge 的 `LaifenLocal` 平台配置中设置：

```json
"adaptiveLightingMode": "independent",
"adaptiveReferenceBrightness": 70
```

重启桥接后生效，无需重新配对；已保存的有效自适应计划继续使用。改回 `"adaptiveLightingMode": "apple"` 并重启即可回退。手动设置色温、检测到灯端色温改变或灯内日光同行启用，仍会停用自适应照明。

## 验证范围

自动测试将解耦结果与未修改的 HAP 原生算法在固定参考亮度下逐点对照，覆盖多段过渡/停留边界、变化的亮度系数、时钟偏差、70% 与 100% 参考、亮度范围限制、色温限幅、通知节流、恢复/刷新/到期、手动覆盖及真实亮度显示。

适配接口基于 Homebridge 2.4.0 / HAP-NodeJS 2.2.2。未来依赖升级仍需跑对照测试；无法保证未来任何新协议都不需适配。灯具色温的物理准确性仍需仪器测量，协议回报不是色温计读数。
