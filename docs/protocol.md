# 观察到的 LFFL01-P 协议

来源：用户自己的灯、iPhone App 的 PacketLogger ATT 记录，以及独立 Mac BLE 写入和用户实体反馈。这里提供结构及命令向量，不分发包含个人设备身份或周围设备数据的原始日志。

服务 `0000ff01-0000-1000-8000-00805f9b34fb`，特征 `0000ff02-0000-1000-8000-00805f9b34fb`（Write / Notify）。每次连接通过服务发现获取特征对象，不写死 ATT handle。FF10、FE59 和 Nordic DFU 形状服务未用于控制。

## 帧

`AA（发送）/5A（接收） | 类别 | 命令 | 序号8位 | payload长度BE16 | payload | XOR`

所有字节 XOR 为 0。控制 ACK 的类别为请求类别 OR C0，命令和序号与发送一致，已知成功 payload 为 00。通知序号可能独立变化，状态响应不能仅靠序号和某次查询唯一关联。

| 操作 | 类别/命令 | 数据 |
| --- | --- | --- |
| 状态查询 | 41/03 | 无 |
| 总开关 | 01/08 | 00/01 |
| 上灯开关 | 03/01 | 00/01 |
| 上灯亮度 | 03/02 | 1–100 |
| 下灯开关 | 03/03 | 00/01 |
| 下灯亮度 | 03/04 | 1–100 |
| 共用色温 | 03/05 | 2900–5700 K，BE16 |
| 原生自动亮度 | 03/0C | 00/01 |

不发送猜测的亮度 0：HomeKit 的 Brightness=0 转换为该路关闭。控制 ACK 后继续查询新状态，最多等待约 6 秒；状态落后时只轮询，不自动重发控制。实际物理反应仍需确认。

## 43 字节状态 payload（81/03）

| 偏移 | 内容 |
| --- | --- |
| 0–14 | ASCII 名称，NUL 填充 |
| 15–20 | 灯回报的 6 字节身份地址 |
| 21 | 总电源状态 |
| 22 / 23 | 上灯开关 / 亮度 |
| 24 / 25 | 下灯开关 / 亮度 |
| 26–27 | 色温 K，BE16 |
| 28 | 入座感应开关 |
| 29 | 感应距离编码，捕获过远=200 |
| 30–31 | 入座感应延迟秒数，BE16 |
| 32 | 原生自动亮度开关 |
| 33 | 日光同行开关 |
| 34–38 | 夜间模式开关、开始/结束小时分钟 |
| 39–40 | 延迟关灯开关、分钟 |
| 41–42 | 未确定 |

没有识别出实时环境 lux 或占用状态字段。不能声称灯完全不回传这类信息，只能说当前状态与抓包未识别到。未验证功能保持只读解析，不开放写入。

`tests/fixtures/app-command-vectors.json` 只含捕获的上述控制/查询帧，不含设备地址。协议测试中的状态帧明确为合成匿名数据，用于验证不同设备身份和拒绝错误目标。
